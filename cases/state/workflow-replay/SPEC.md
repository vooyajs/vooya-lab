# Workflow Replay Specification

## Identity and status

- Portfolio class: `flagship candidate` (registered as `foundation` until the
  remaining acceptance evidence is complete)
- Maturity: `experimental`
- Execution: `precompiled`
- Source editable: `false`
- Distribution: `demo-only`
- Owning repository: `vooyajs/vooya-lab`
- Last verified: `2026-08-30`

## User outcome

Run, inspect, rewind, and deterministically replay a typed approval workflow
whose rules and audit log live in Rust while Vue renders the complete product
interface.

## Question

Can one instance-scoped Vooya Rust Store own non-trivial domain invariants,
snapshots, and replay while Vue remains the only renderer and receives a small
structured snapshot after each user action?

## Why this boundary?

### Host owns

- accessible workflow controls, timeline, status cards, and responsive layout;
- page-level scenario copy, selected replay target, and presentation state;
- focus, button availability, and product navigation.

### Rust/WASM owns

- the allowed transition graph and terminal-state invariants;
- the append-only audit events, cursor, rewind, and deterministic replay;
- invalid-transition accounting and the structured public snapshot;
- one instance-scoped Store lifecycle and disposal.

### GPU relationship

`not-applicable`

This is branch-heavy domain state and host-rendered UI. WebGPU/WebGL would add
no useful ownership boundary.

### Boundary crossing

- Inputs: coarse imperative actions (`advance`, `rewind`, `replay_to`,
  `attempt_invalid`, `reset`) with primitive arguments.
- Outputs: one cached structured snapshot containing stage, cursor, event count,
  invariant status, available actions, and at most six visible audit labels.
- Update pattern: one action crosses on a user gesture; Rust coalesces internal
  mutation and publishes one snapshot notification.

### Vooya value

- generated Rust Store factory and the Vue Store adapter;
- structured snapshot conversion and typed action declarations;
- cached snapshot identity, subscription, instance isolation, and disposal;
- build integration and source-linked diagnostics without handwritten
  `wasm-bindgen` store glue.

### Alternatives

- a plain TypeScript reducer and local Vue state;
- a Pinia/Zustand store with the rules rewritten in TypeScript;
- a handwritten wasm-bindgen handle, callback list, snapshot encoder, and
  framework lifecycle adapter.

## Experience and source

- Live Workbench: Preview and Source share one fixed-height surface; wide
  desktops use split view and compact layouts use Preview/Source tabs.
- Preview: a host-rendered approval console with current stage, invariant seal,
  deterministic event ledger, cursor, and replay rail.
- Controls and reset: advance, rewind one step, replay to the selected cursor,
  attempt one invalid transition, and reset the instance.
- Source files: Rust Store, Vue host, case CSS, metadata, spec, and public entry.
- Props/events: Store actions in; cached structured snapshots out through the
  generated subscription contract. No DOM component props/events are used.
- Copy/install action: active-file copy only; a complete Store package awaits
  the precompiled-consumer contract.
- Responsive and reduced-motion behavior: controls wrap, the ledger owns its
  scroll, and status changes do not require animation.

## Execution and isolation

- Compiler/runtime path: repository build to `wasm32-unknown-unknown` through
  the existing Vooya Vite pipeline.
- Worker/frame boundary: none; this is a trusted instance-scoped Rust Store in
  the same application realm.
- Network/storage policy: no network, persistent storage, or external assets.
- Cancellation and disposal: actions are synchronous and bounded; the Vue
  composable unsubscribes and disposes the owned Store on unmount.
- Required headers/capabilities: ordinary WASM support; no GPU or cross-origin
  isolation requirement is claimed by the case itself.

## Distribution

- Exported files: those listed in `case.json`.
- npm packages: `@vooya/vue = 0.1.0-alpha.10`.
- Rust crates/features: coordinated `vooya` runtime only.
- Cargo/TypeScript changes: generated by the Lab build; the current host must
  temporarily narrow the generated snapshot because concrete Store snapshot
  declarations are tracked by upstream issue #105.
- Assets, license, and attribution: none.
- Deployment requirements: ordinary static Vooya WASM hosting.

Distribution remains `demo-only` until Vue and React can consume one packed,
typed Store artifact without Rust tooling or Lab internals.

## Known gaps and upstream issues

- [vooyajs/vooya#105](https://github.com/vooyajs/vooya/issues/105): generated
  Rust Store snapshots currently fall back to `Record<string, unknown>`; the
  case may use one explicit temporary host-side narrowing, never a second ABI.
- The published `@vooya/vite@0.1.0-alpha.10` emits the Vue Store factory but
  not the generated `useWorkflowReplay` runtime export declared by its `.d.ts`;
  this case therefore uses the public low-level `useVooyaStore` adapter until
  the already-landed generator path reaches a release.
- [vooyajs/vooya#61](https://github.com/vooyajs/vooya/issues/61): State
  Components/Stores remain an open post-beta product boundary even though the
  current alpha implementation is usable for evidence.
- [vooyajs/vooya#54](https://github.com/vooyajs/vooya/issues/54): user-defined
  type/schema parity remains the adjacent ABI owner.
- React parity, packaged precompiled consumption, explicit double-instance
  browser evidence, and failure injection are not yet implemented.

## Extraction decision

Keep the workflow and UI case-local. Extract only if a second case needs the
same replay/audit domain behavior. The Store/Workbench infrastructure already
belongs to Vooya Core and `packages/ide`; do not duplicate it locally.

## Non-goals

- A generic workflow engine or BPMN editor.
- Global application state, routing, persistence, networking, or collaboration.
- A claim that Rust is faster than a TypeScript reducer.
- Moving Vue rendering or accessibility into Rust.
- Arbitrary browser compilation or untrusted Store execution.
