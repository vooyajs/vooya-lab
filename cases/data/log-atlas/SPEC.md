# Log Atlas Specification

## Identity and status

- Portfolio class: `flagship`
- Maturity: `live`
- Execution: `precompiled`
- Source editable: `false`
- Distribution: `demo-only`
- Owning repository: `vooyajs/vooya-lab`
- Last verified: `2026-08-30`

## User outcome

Explore a local trace corpus, apply a Rust `regex` query and duration threshold,
and inspect a responsive waterfall without uploading observability data.

## Question

Can Vooya keep a long-lived trace model behind a typed component boundary while
Vue sends coarse query controls instead of shuttling every row through
JavaScript?

## Why this boundary?

### Host owns

- query, duration, and time-window controls;
- accessible page explanation and reset behavior; and
- gallery navigation and source inspection.

### Rust/WASM owns

- parsing a deterministic local trace format;
- the 1,800-span corpus and its service/error aggregations;
- `regex` compilation and row filtering; and
- projection of at most 32 visible rows into the component waterfall.

### GPU relationship

`not-applicable`. Parsing irregular text, matching regular expressions, and
maintaining an indexed domain model are CPU tasks. A GPU renderer could help
only after the data is projected; the current DOM waterfall is small enough
that it would add complexity without answering the case question.

### Boundary crossing

- Inputs: one query string and two numeric filter props.
- Outputs: a component-owned summary and at most 32 visible rows.
- Update pattern: coarse host actions cross the boundary; the full corpus does
  not round-trip through JavaScript.

### Vooya value

- a Rust-file build with an ordinary ecosystem crate;
- generated Vue mounting and typed props;
- component-owned styles, update lifecycle, and deterministic unmount; and
- one inspectable case unit instead of bespoke glue spread across the app.

### Alternatives

Plain TypeScript is credible for a smaller dataset and should remain the default
when no Rust ecosystem or shared-code reason exists. A custom `wasm-bindgen`
wrapper could expose the same engine, but its adapter, prop conversion,
lifecycle, style loading, and packaging contract would be case-owned. Uploading
logs to a server changes the privacy and offline product rather than merely the
implementation.

No speed claim is made. The live proof is ownership and integration shape.

## Experience and source

- Preview: spectral trace waterfall with service, route, duration, and status in
  a stable-height viewport; filters scroll inside the stage instead of shifting
  the rest of the case page.
- Controls: query presets, regex input, duration threshold, window, and reset.
- Source files: Rust, scoped CSS, Vue host, metadata, spec, and case entry.
- Props: `query`, `minimum_duration`, and `window`.
- Copy/install: the Workbench toolbar can copy its currently active source file;
  a dependency-complete copy bundle still waits on a Cargo mutation path.
- Reduced motion: the case uses no required animation.
- Small screens: row metadata collapses before the trace bars; controls wrap.

## Execution and isolation

- Rust compiles during the repository build to `wasm32-unknown-unknown`.
- The case is precompiled and read-only; no browser compiler is implied.
- It performs no network or storage access and claims no sandbox boundary.
- Vooya owns component mount/update/disposal; the module-level corpus is shared
  only within the generated WASM instance.

## Distribution

- Exported files: those listed in `case.json`.
- npm packages: `@vooya/vue` through the Lab host.
- Rust crates: `regex = 1.12.2` plus the coordinated Vooya runtime.
- Assets: none; all rows are deterministic data generated by Rust.
- Deployment: ordinary static Vooya WASM hosting; no cross-origin isolation.

Distribution remains `demo-only` until the case can export a complete Cargo,
host, style, and configuration unit without importing application internals.

## Known gaps and upstream issues

- The deterministic corpus makes the capability repeatable but does not yet
  exercise browser `File` streaming, binary transport, or cancellation.
- The current Vooya component API rebuilds the view on coarse prop updates;
  future store/instance work should measure whether the parsed corpus can be
  scoped per mounted instance without module-global state.
- Browser-compiler Gate 2 supports only its reviewed fixed ABI and is not a
  compatible compiler profile for this arbitrary component yet.

## Extraction decision

Keep the parser, trace schema, and waterfall case-local. Consider a package only
after a second observability or data-explorer case needs the same typed query
engine and lifecycle contract.

## Non-goals

- claiming Rust is universally faster than JavaScript;
- moving host forms, routing, or accessibility into WASM;
- replacing WebGPU/WebGL; or
- accepting untrusted uploaded files before limits and cancellation exist.
